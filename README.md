# Мои Финансы · Family Finance v2.0

Адаптивное PWA для личного и семейного финансового учёта: React + TypeScript + Vite + Dexie/IndexedDB + Google Apps Script + Google Sheets. Исходники размещаются в GitHub. Cloudflare Worker используется **только** как HTTPS-транспорт из статического PWA к опубликованному Apps Script, потому что обычный CORS-запрос из GitHub Pages в Apps Script не работает надёжно.

## Состав релиза

- Мобильный, планшетный и ПК-интерфейсы; светлая/тёмная тема, скрытие сумм, поиск, отчёты, CSV.
- Семейные профили с индивидуальными шестизначными PIN. На сервере проверка PIN, блокировка перебора, сессии и ограничения по владельцу/общим счетам.
- Банки, дебетовые/кредитные карты, наличные, накопления, долговые счета.
- Транзакции доход/расход/перевод, целые копейки, UUID, автор и подтверждение по серверу. Перевод **не** попадает в доходы и расходы.
- Категории, бюджет по месяцам, графики, кредитные ставки/платежи, долги и накопительные цели.
- Календарь повторяющихся доходов/расходов, ручное подтверждение оплаты: **план сам по себе никогда не меняет баланс**.
- Офлайн-очередь по каждому участнику, повтор отправки при подключении, запрашиваемый серверный снимок порциями по 300 записей.
- Напоминание при открытом PWA после выбранного времени; «Нет операций сегодня» для законного пропуска дня. Email-напоминание при закрытом приложении через часовой триггер Apps Script (если разрешено пользователем).
- Ссылка Apps Script сохраняется в IndexedDB; подключение через URL или QR. После связки профиль идентифицируется сервером.
- Сессионный токен на устройстве зашифрован AES-GCM ключом, производным от PIN. Сервер хранит только HMAC токена, не открытый токен.

## Порядок развёртывания

### 1. Google Apps Script + таблица

```bash
npm install
npx clasp login
cp .clasp.json.example .clasp.json
```

Создайте **отдельный проект Apps Script** (не используйте чужой/рабочий скрипт) и скопируйте его `scriptId` в `.clasp.json`. **Не публикуйте** этот файл или OAuth-данные. Перед первым `clasp push` проверьте `scriptId`; `clasp push` заменяет удалённые исходники.

```bash
npm run gas:push
```

**Важно:** убедитесь, что через `clasp` загружены `Code.gs`, `Sync.gs`, `Reminders.gs`, `EntryPoints.gs` и `appsscript.json`. В меню «Выполнить» выбирайте `setupBackend`, `bootstrapOwner`, `checkBackend` или `installReminderTrigger` **без `_`**. `ftext_()` — внутренний помощник из `Sync.gs`, запускать его вручную нельзя. Если возникает `ftext_ is not defined`, значит отсутствует/не загрузился `Sync.gs`. После создания базы запустите `checkBackend` для диагностики.


В редакторе Apps Script: запустите `setupBackend()` вручную и подтвердите разрешения. Это создаст Google-таблицу и запишет `FINANCE_SHEET_ID` в Script Properties; повторный запуск добавит отсутствующие колонки без удаления существующих записей.

В **Настройки проекта → Свойства скрипта** добавьте `INITIAL_ADMIN_NAME` (имя), `INITIAL_ADMIN_PIN` (шесть цифр), `INITIAL_ADMIN_EMAIL` (при необходимости), `FAMILY_TIMEZONE` (например, `Europe/Moscow` или `Europe/Stockholm`). Запустите в редакторе `bootstrapOwner()` один раз. PIN удаляется из Script Properties после создания администратора.

Опубликуйте **Развернуть → Новое развёртывание → Веб-приложение → Выполнять от моего имени; доступ: Все (включая анонимных)**. Скопируйте URL вида `https://script.google.com/macros/s/DEPLOYMENT_ID/exec`. Доступ для анонимных запросов нужен транспортному Worker, но сама финансовая запись и выдача данных требуют авторизации по серверной сессии. Ограничьте доступ к самой Google-таблице доверенными владельцами.

Для каждого обновления Apps Script выполните `npm run gas:push` и **обновите версию существующего веб-развёртывания**. Один `clasp push` не обновляет уже опубликованную версию `/exec` автоматически.

### 2. HTTPS-шлюз Cloudflare Worker

На машине, где вы авторизованы в Cloudflare:

```bash
cd worker
npx wrangler login
npx wrangler deploy
```

Worker **не хранит** PIN, токены, бюджет или таблицу: он просто передаёт JSON через HTTPS. Его исходник в `worker/index.js`; список разрешённых сайтов начинается с `https://morkov-d.github.io`. При смене домена обновите список. Не используйте открытый Worker как универсальный прокси.

Используем развёрнутый адрес, предоставленный владельцем: `https://family-finance-gateway.massahg.workers.dev`. Наличие URL не подтверждает успешность работы Worker; проверьте его после установки.

### 3. GitHub Pages PWA

Адрес шлюза уже настроен в `.env.production` и в GitHub Actions: `https://family-finance-gateway.massahg.workers.dev`. Это публичный URL, не секрет. Для изменения адреса обновите оба файла. `VITE_API_URL` используется только на этапе сборки Vite.

В **Settings → Pages → Source** выберите **GitHub Actions**. Push в `main` запустит тесты, сборку и публикацию. Запланированный адрес PWA:

`https://morkov-d.github.io/family-finance-pwa/`

Если Worker не развёрнут, локальный режим работает, а облачная авторизация и синхронизация недоступны. Приложение показывает явное предупреждение.

### 4. Первый вход семьи

1. На первом экране выберите подключение к готовой семейной базе.
2. Вставьте ссылку на Apps Script `/exec` или отсканируйте QR с **доверенного** устройства владельца.
3. Нажмите «Найти семью», выберите профиль и введите его шестизначный PIN.
4. Администратор может добавить членов семьи; у них будут свои PIN, личные счета и доступ к общим.
5. Создайте счета, внесите стартовые остатки и операции; при отсутствии сети они остаются в очереди. Индикатор и кнопка синхронизации находятся в настройках.

При установке на новый телефон **не создавайте новую локальную семью**, а подключитесь к тому же серверу через URL и PIN.

### 5. Ежедневные email-напоминания

Включите напоминания в профиле и укажите рабочий email, желаемый час и часовой пояс. В редакторе Apps Script **один раз** вручную выполните `installReminderTrigger()`. Скрипт будет проверять за текущий день факт операции от участника либо его отметку «Нет операций» и отправлять максимум одно письмо в день в пределах квот MailApp. Часовой триггер может сработать не ровно в желаемую минуту.

**Push при полностью закрытом PWA на телефон** не включён в этот релиз: для него необходима отдельная служба Web Push с VAPID-ключами и подписками устройств. Не рассчитывайте на фоновый `setTimeout`.

## Тесты и запуск

```bash
npm install
npm run test
npm run build
npm run dev
```

Запуск из браузера `localhost` через Worker требует задать `ALLOW_LOCALHOST=true` в Worker-конфигурации **только для разработки** и `VITE_API_URL` в `.env.local` (см. `.env.example`). Для публичной версии оставьте `ALLOW_LOCALHOST=false`.

## Ограничения и безопасность

**Прежде чем использовать для настоящих семейных финансов, проведите сквозное тестирование на двух телефонах с реальной Google-таблицей и проверьте права, восстановление очереди и резервную копию.** Данные финансовых операций в IndexedDB **не зашифрованы** — это особенно важно на общих/потерянных устройствах. PIN и серверная сессия обеспечивают контроль доступа в приложении, но не превращают IndexedDB в защищённое хранилище от злоумышленника с доступом к браузерному профилю. Сторонние приложения не получают доступ к финансовой Google-таблице; владелец таблицы должен также следить за доступами к своему Google-аккаунту.

`bootstrapOwner`, шлюз, Google Sheet и триггер здесь не создаются автоматически: для них нужны ваши учётные записи и разрешения. Не помещайте ссылки, PIN, email, секреты и финансы в Issues/публичный репозиторий.

Кредиты/карты дают **оценочные** графики; фактические комиссии, льготные периоды и проценты нужно сверять с условиями банка. Долги и накопительные цели — отдельные регистры, а изменения по ним не проводят банковскую транзакцию автоматически. Бюджеты общие по категориям и сохраняются последним изменением; одновременное редактирование с разных устройств пока не использует историю версий.

> В некоторых корпоративных Google Workspace доменах анонимное развёртывание Apps Script запрещено политиками администратора. В таком случае Worker получит ошибку, и потребуется иной способ аутентификации или отдельный серверный API.
